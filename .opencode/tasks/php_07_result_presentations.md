# PHP-07 — Специальное представление или JSON

## Цель и границы

В карточке задания появится одно специальное представление: для `echo-test` v1 читаемый текст результата показывается сразу, а полный публичный JSON можно открыть без нового запроса. Все остальные допустимые результаты, включая `word-count` v1, по-прежнему показываются форматированным JSON; одно новое действие будет проверено в браузере от выбора из каталога до открытия результата по ID задания без специальной формы или карточки.

**Приоритет:** единственный открытый согласованный пункт в `/opt/php-wiki-plugin/docs/todo.md`; совпадает с PHP-07 в `docs/php_wiki_jobs_roadmap.md`. PHP-05 (`e75b865`, карточка) и PHP-06 (`4e466ea`, каталог/универсальная форма) закрыты. Backend T26 закрыт. В `/opt/go-pet` T27 ещё `[ ]`: код миграции `000007`, runner и `TestWordCountBackend` есть только в незакоммиченном наборе T27, а в `.opencode/tasks/27_word_count.md` зафиксированы положительные результаты backend-проверок. Это не подтверждение Human Sign-off или развёртывания. По тому же плану backend T27 принимается отдельно, а закрытие всего T27 ждёт wiki E2E после PHP-06/07. Поэтому fixture-часть PHP-07 можно начинать сейчас; финальный сквозной запуск привязать к принятой backend-ревизии T27, не требуя от T27 предварительной отметки `[x]`. Если ревизия ещё не принята, оставить PHP-07 открытым и сообщить блокер; не принимать и не коммитить backend от имени PHP-07.

Один шаг в `/opt/php-wiki-plugin`. Не менять API, `PetarClient.php`, `action.php`, ACL, форму отправки, маршруты, задания/курсор, backend-код или рабочую БД. Не добавлять отдельный renderer для `word-count`, новых зависимостей UI и загрузки renderer-ов снаружи. Не заменять штатную fixture-приёмку реальным backend.

## Подтверждённое исходное состояние

- `script.js::initializeJobs/openCard` уже выводит `JSON.stringify(data.result, null, 2)` через `textContent`, только для ответа 200 по выбранному `job_id`. `closeCard` очищает результат и инвалидирует предыдущий запрос; смена фильтра и обновление закрывают карточку. В `syntax.php::renderJobs` есть скрытый `<pre class="petar-job-public">`, но нет отдельной области представления или переключателя JSON.
- `PetarClient.php::getJobResult` пропускает ровно публичный объект `{type,version,data}` с непустым типом, целочисленной `version === 1`, объектом `data`, лимитом 1 МиБ; `tests/contract/action_test.go::TestJobResultAction/bad_version` проверяет безопасный 502 для v2. PHP-07 выбирает по паре на UI-уровне, но не расширяет BFF-контракт. Синтетическая v2 в JS-тесте проверяет только диспетчеризацию, не доступность v2 через HTTP.
- `tests/contract/ui_test.go::TestJobsUIBehavior` прогоняет `tests/contract/ui_behavior.js::runJobs` на EN/RU. Он уже проверяет текстовый fallback, чужой/запоздалый результат, смену/закрытие карточки и ошибки. `tests/acceptance/{fixture.js,smoke.spec.js}` идут через настоящий DokuWiki AJAX; два успешных документа с фикстурным типом `echo` и полем `marker` показываются как JSON. Это не реальный тип: `/opt/go-pet/scripts/spool-runner.sh::prepare_public` публикует `echo-test` v1 с `data.echo`, а для T27 — `word-count` v1 с `data.words`.
- Эти выводы подтверждены чтением исходников, тестов и истории. Plan не запускал RED/GREEN, quality gate или E2E. Доступность принятой T27-ревизии и успешный прогон нового стенда Build подтвердит отдельно.

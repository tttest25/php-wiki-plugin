# petar: общий журнал, формы действий и карточки

Согласованная дорожная карта для `/opt/php-wiki-plugin/docs/todo.md`. Пункты ниже открыты; переносить по ID без дублирования. Один шаг — один атомарный коммит после приёмки. Общий доступ без разделения по автору только для вошедших `ai`/`admin`. Браузер работает через DokuWiki AJAX, HTTP-транспорт плагина — только `PetarClient` и `DokuHTTPClient`.

- [ ] **PHP-01: Прямые запросы BFF без редиректов.** Запретить автоматические переходы для readyz и submit; 3xx не превращается в успех, при штатных 200/201 поведение прежнее. Новые методы чтения используют ту же политику.
- [ ] **PHP-02: Отличать отказ от неизвестного исхода.** Подтверждённый backend 400 для неверного ввода → безопасный отказ; потеря ответа → предупреждение без автоматического повторного POST. Не раскрывать сырые ошибки.
- [ ] **PHP-03: Воспроизводимая приёмка плагина и Playwright.** Из чистого checkout запустить контрактные тесты и минимум один браузерный smoke в изолированной DokuWiki. Без Browser MCP, рабочей БД, внешних платных CLI; обеспечить воспроизводимый запуск и диагностику сбоев.
- [ ] **PHP-04: Общий журнал `{{petar>jobs}}`.** `{{petar}}` остаётся формой. Одна строка — один job. Общий список для `ai`/`admin`, фильтры всех пяти статусов, курсор, «Ещё», «Обновить», пустое состояние и ошибка. Без прямого доступа к backend и без данных до ACL. Использует существующий `GET /api/v1/jobs`, не зависит от T22–T27.
- [ ] **PHP-05: Карточка завершённого задания.** Открывать completed/failed из выбранной строки с сохранением фильтра. Показать ID процесса и job, инструмент, итог и даты; успешный результат или публичное сообщение об ошибке — по контракту T26. Никогда не подставлять артефакт соседнего задания. Для завершения нужны PHP-04 и T26.
- [ ] **PHP-06: Динамический каталог и универсальная форма.** После T23/T24 выбирать действие и версию из API через BFF. Для известных действий сохранить привычные формы; для прочих — ввод JSON-значения. Невалидный JSON не уходит из формы, правила действия проверяет БД. Новое действие не требует изменения PHP/JS.
- [ ] **PHP-07: Специальное представление или JSON.** Выбирать зарегистрированное представление по типу и версии результата; иначе выводить форматированный публичный JSON как текст. И для специального представления доступен просмотр JSON. После PHP-05 проверить запасной вариант на фикстуре, финально после PHP-06 и T27 — браузерный сценарий word-count без специальной формы/карточки.

## Первая итерация: PHP-04

1. В `tests/contract` начать с `TestSyntaxJobsMode`: разобрать штатным парсером DokuWiki страницу, содержащую оба макроса; ожидать один виджет журнала и одну форму. Нынешний `syntax.php::connectTo` распознаёт только `{{petar}}`; текущий `ui_test.go` напрямую вызывает `render` и не проверяет lexer. Ожидаемый RED — не распознан журнал. RED при подготовке карты не запускался.
2. GREEN: распознать точный новый макрос в `syntax.php`, передать режим из `handle` в `render`; для журнала вывести отдельный контейнер без формы submit, с отключённым кэшем. Тесты для anonymous/ordinary: ни данных, ни элементов управления; две разрешённые роли; одновременный рендер и независимость виджетов.
3. Добавить HTTP-контракт для нового GET-действия `jobs` в `action.php` и метода `PetarClient`. До реализации ожидается 404. Проверить ACL до запроса к backend, GET-only, request ID, валидацию status/cursor и нормализацию полей. Go уже отдаёт JSON-массив, а не конверт: одна строка UI содержит только job_id (из id), process_id, tool, status и даты. Не пересылать payload, result_path, error_msg. Старый `action=status` остаётся резервом. Не следовать редиректам на новом маршруте даже если PHP-01 ещё не выполнен.
4. Поведенческие тесты JS → UI: 20 строк на страницу; получить 21 для определения наличия следующей, курсор — ID последней показанной, не скрытой строки. Фильтры «все» и по одному из pending/dispatched/in_progress/completed/failed, ручное обновление и сброс курсора при смене фильтра. Различать «пусто» и «ошибка», игнорировать запоздалый ответ предыдущего фильтра. Локализации RU/EN; рендер текста без HTML-интерпретации.
5. Из `/opt/php-wiki-plugin` с `dokuwiki` и смонтированным checkout: `GO111MODULE=off go test -count=1 -v ./tests/contract -run '^TestSyntaxJobsMode$'` для RED/GREEN; затем `GO111MODULE=off go test -count=1 -race -timeout 120s ./tests/contract`, `GO111MODULE=off go vet ./tests/contract`, `node --check script.js`, `git diff --check`. Для каждого изменённого PHP-файла — `docker exec dokuwiki php -l /config/dokuwiki/lib/plugins/petar/<файл>`. После JS/CSS выполнить `docker exec dokuwiki touch /config/dokuwiki/conf/local.php`. Браузерная приёмка на странице с обоими макросами; до PHP-03 допустима ручная, затем автоматизировать в изолированном Playwright smoke. Review ACL, публичных полей и курсора → diff и результаты → Human Sign-off → один коммит с отметкой и уникальным subject в `docs/todo.md`.

Не включать в PHP-04 каталог действий, карточку, скачивание файлов или внедрение Playwright. Архитектурную документацию синхронизировать в рамках согласованного изменения.
